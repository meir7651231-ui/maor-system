## 3א. דמו מקצה לקצה (ממשק ↔ שרת, dry-run)
```bash
cd collect-agent && ./demo.sh      # בונה את web/ אם יש Node, ומגיש: http://127.0.0.1:8000/app/#/dashboard
```
- **מצב חי:** הממשק מזהה את השרת (`GET /health` באותו origin, ו**רק** אם `dry_run:true`, אחרת מסרב) ועובד מול ה-API. מקורות הנתונים: `/dashboard` (חשבוניות וסיכומים), `/reminders?status=pending_approval` (התור), `/reminders/{id}/preview` (**הנוסח המדויק מהשרת**, SMS ומייל, כולל שם השולח וחלון השליחה בשעון ישראל). "אשר ושלח" מפעיל `approve` ואז `dispatch`, ותיבת היוצאים מתעדכנת. חסימות (`no_contact` וכו׳) מוצגות, והכפתור מושבת. כרטיס "סימולציה: לקוח עונה" שולח `POST /inbound` ומראה את הסיווג ואת המענה האוטומטי.
- **מצב מוק:** כשאין שרת (למשל אירוח סטטי) הממשק עובר לנתוני `data/demo.ts`. תג בסרגל הצד מראה באיזה מצב הוא נמצא.
- הבקאנד מגיש את `web/dist` ב-`/app/` רק אם הוא נבנה (`WEB_DIST` לשינוי). `/ui` הרזה לא נפגע. בדיקה: `test_web_app_served_when_built`, ו-`demo.sh --check` מאמת את `/app/`.
- **«דורש טיפול שלך»** (חי): לקוח מושהה ("שילמתי") ⇒ «↻ חידוש תזכורות» (`POST /customers/{id}/resume`), והצעות פריסה שממתינות ⇒ «✓ אישור ההצעה» (`POST /plans/{id}/approve`, נשלחת ללקוח ב-dry-run). שתי הפעולות באישור בלחיצה כפולה (חימוש ל-4 שניות).
- **«תשובות לקוחות» (`#/inbox`, חי):** כל תשובת חייב ⇒ כרטיס עם סיכום לבעל העסק, פעולות לבדיקה ודחיפות (דחוף/לטיפולך/שגרתי), וטיוטת מענה של מנוע השיחה. אפשר לערוך, «✓ אשר ושלח» (`/conversation/drafts/{id}/approve`, נוסח שנערך עובר את מסנן הניסוח בשרת) או «✗ סגירה בלי מענה». דחיית המסנן מוצגת בעברית (`explainViolation`: marketing ⇒ "תוכן שיווקי"). המונה בסרגל הצד = מספר הכרטיסים בתור.
- הוכחה: `node web/e2e/live.mjs` מרים שרת `DEMO=1` אמיתי ובודק בדפדפן: תור של 2, תזכורת חסומה שאי אפשר לאשר, נוסח מהשרת עם קישור תשלום והסרה, אישור, ‎+2 ביומן היוצאים, תשובת לקוח מסווגת, חידוש לקוח מושהה (מאומת בשרת), הצעת פריסה ⇒ אישור ⇒ ‎+1 ביומן, טיוטת מענה שנערכה עם "מבצע" ⇒ נחסמת עם הסבר בעברית ⇒ נוסח נקי ⇒ נשלח (+1 ביומן), ו-0 שגיאות קונסולה. צילומי "עמוד מלא" נעשים בהגדלת ה-viewport (`fullShot`) — `fullPage` של Playwright מציג סרגל-צד sticky במקום שגוי.

## 4. כללי תוכן (נאכפים בבדיקות, בשני הצדדים)
- **מקור האמת לנוסחים = `app/templates.py`** (סשן הבקאנד). `web/src/lib/message.ts` הוא מראה אות-באות, ובדיקה `tests/lib.check.ts` קוראת את `templates.py` ונכשלת על כל סטייה (נבדק במוטציה). שינוי נוסח: קודם בבקאנד, אחר כך כאן.
- כל SMS: מתחיל ב-`{שם העסק}:` (זיהוי השולח), **קישור תשלום**, **קישור הסרה** (`/u/{token}`). כל מייל: קישור+כפתור תשלום, `List-Unsubscribe`.
- ⚖️ חוק התקשורת §30א: תזכורת על חשבונית של לקוח קיים = הודעה שירותית, **רק אם נקייה משיווק** ⇒ אין מבצע/הנחה/הטבה/קופון וגם אין איומים (`MARKETING_WORDS`/`THREAT_WORDS` בבקאנד; אותה רשימה בבדיקת הממשק). פירוט: `docs/MVP-SPEC.md §4א`, `docs/CHANNELS-RESEARCH.md`.
- SMS בעברית: 70/67 תווים למקטע — הנוסחים כ-3 מקטעים; המונה בממשק מזהיר מעל 3 ואם נמחק קישור התשלום.
- חלון שליחה: א׳–ה׳ 9–19, ו׳ 9–12, לא שבת/חג (מראה של `app/policy.py` ב-`web/src/lib/policy.ts`). אין בחוק מגבלת שעות ל-SMS שירותי — זו מדיניות נגד הטרדה.
- "תזכורת אחרונה" והודעה ראשונה ללקוח — תמיד באישור הבעלים.

## 6. הרצה ובדיקה
```bash
cd collect-agent/web && npm ci
npm run dev          # http://localhost:5173
npm test             # 9 בדיקות (node:test) — כולל מיפוי /dashboard ושעון ישראל; — פורמט, נוסחים, מקטעים, סולם, מדיניות שעות, סטטיסטיקה, סנכרון מול templates.py
npm run build        # typecheck + build
node e2e/live.mjs [dir]    # דמו חי מול שרת DEMO=1 (ראו §3א)
node e2e/shots.mjs <dir>   # Playwright (מוק): כל המסכים + אשר-ושלח + חיפוש + מובייל 390px, 0 שגיאות קונסולה
```
