## הכרעות הבעלים (30.7 — מצילומי המובייל + שלוש דרישות חדשות)
15. **"כל אלה"** — מודאל מימוש מותאם-סוג, תיקון בורר השנה העברית, סידור מובייל.
16. **פגישה = מקום + תפיסת לוח דו-כיוונית** — פגישת ליווי משויכת לחדר קיים; אי-אפשר לתפוס חדר תפוס, וחדר שנתפס בפגישה חסום לשאר המערכת. **חור מבוקר בבידוד באישור הבעלים: פגישה-עם-חדר בלבד. הכסף נשאר מבודד לחלוטין.**
17. **מתנת-חג = בחירת חגים** — בורר חגים מרובה; "מה מגיע" רק לחגים שנבחרו.
18. **קריאה ב׳ — פריטי קטלוג עצמאיים:** הרכיבים הופכים לפריטים (ShopItem) עם מלאי/תוקף/חנות משלהם; חבילה מרכיבה פריטים. **מלאי אחד משותף** גם כשפריט מופיע בכמה חבילות.

**ברירות ארכיטקט (ניתנות לדריסה):** פריט מחזיק ברירות-מחדל (שווי/מחיר-סמלי/מלאי/תוקף/חנות) והרכיב-בחבילה יכול לדרוס שווי/מחיר בלבד · מיגרציה אוטומטית: כל רכיב קיים מוליד פריט (בלי איחוד אוטומטי — איחוד ידני של המשרד) · פגישה בלי חדר נשארת מבודדת (לא נוגעת בלוח הראשי).

## אשכול 16 · תיקוני הצילומים (`חנות 16 ·`)

1. **RedeemModal מותאם-סוג:**
   - `meeting` — תאריך + הערה בלבד. אפס שדות כסף, אפס שורת מחיר. ‏paid/value נשמרים 0 (אין S-).
   - `coupon` — שורת מחיר + "לתשלום" בלבד; "שווי שנמסר" מוסתר (value נלקח אוטומטית מהפריט).
   - `gift`/`holidayGift` — כמו היום.
2. **בורר השנה העברית (HebDateInput — תיקון רוחבי לכל המערכת):** ה-‎`(5786)` נשבר בכיווניות ונחתך. תיקון: תווית האופציה בלי סוגריים — `תשפ"ו · 5786` עם ‎‏ (RLM) בראשה, ‏CSS על ה-select: ‏`unicode-bidi: plaintext; min-width: 96px`. בדוק ויזואלית בשלוש הסוויטות (demo-walkthrough מצלם).
3. **מובייל בכרטיס השיוך:** שורת הפעולות (חזרה/סטטוס/עריכה/מחיקה) — ‏flex עם `flex-wrap: wrap; gap: 6px` ויישור אחיד; אין שבירה לא-מסודרת ב-≤760px.
4. **בדיקות:** הגנת-מקור — RedeemModal מסתעף לפי kind (מכיל `kind === 'meeting'`) ולא מציג שדות כסף לפגישה; HebDateInput מכיל `unicode-bidi`.

## אשכול 17 · פריטים עם מלאי משותף (`חנות 17 ·`)

**קבצים:** `types/domain.ts` · `store/persist.ts` · `lib/cloud-diff.ts`/`cloud-merge.ts` · `shop/lib.ts` · `useApp.ts` · `CatalogTab/ProductForm/StockModal`.

5. ישות חדשה (מילה-במילה; קידומת `shi`):

```ts
/** פריט קטלוג עצמאי — בעל המלאי/התוקף/החנות. משותף בין חבילות (הכרעה 18). */
export interface ShopItem {
  id: Id;
  name: string;
  kind: ShopComponentKind;
  /** חנות שותפה (kind==='coupon'). */
  storeId: Id | '';
  value: number;
  basePrice: number;
  /** מלאי משותף — undefined = ללא מעקב. */
  stock?: number;
  /** ימי תוקף (kind==='coupon'). */
  validDays?: number;
  active: boolean;
  notes: string;
}
```

6. `ShopComponent` הופך למצביע: מוסיפים `itemId: Id` + דריסות רשות `value?: number; basePrice?: number`; השדות label/storeId/stock/validDays נשארים בטיפוס לתאימות-מיגרציה אך **מקורות האמת עוברים לפריט** (label נגזר משם הפריט; labelOverride רשות אם קיים label ישן).
7. `Db.shopItems: ShopItem[]` + ‏emptyDb + ‏cloud-diff (17 אוספים) + מיגרציה: **לכל רכיב קיים בלי itemId — צור ShopItem מנתוני הרכיב** (name=label, kind, storeId, value, basePrice, stock, validDays, active=true), קבע itemId, ואפס את stock/validDays על הרכיב (עברו לפריט). דטרמיניסטי וחד-פעמי (רכיב עם itemId לא נוגעים). **בדיקת המיגרציה: נתוני SHOP קיימים עם מלאי ומימושים — אחרי מיגרציה המלאי נשמר והמימושים עדיין נספרים.**
8. `shop/lib.ts` — ‏`itemOf(db, comp)` (פריט + דריסות הרכיב) · ‏`itemRemaining(db, itemId): number|null` — מלאי הפריט פחות **כל** המימושים החיים של רכיבים המצביעים עליו בכל החבילות (זה לב הכרעה 18) · effectivePrice/couponExpiry עוברים לשאוב מהפריט+דריסות · needsCare stockOut לפי itemRemaining.
9. UI: פאנל **"פריטים"** בקטלוג (`➕ הוספת {termOf('entity.shopItem','פריט')}`, StockModal עובר לפריט); עורך הרכיבים ב-ProductForm הופך לבורר פריט (select + "➕ פריט חדש" inline) + שדות דריסת מחיר/שווי. מונח חדש: `entity.shopItem`='פריט'.
10. **בדיקות:** פריט בשתי חבילות — מימוש בכל אחת מוריד מאותו מלאי; דריסת מחיר פר-חבילה; מיגרציית רכיבים→פריטים (כולל כפל-ריצה לא יוצר כפולים); cloud round-trip.

## אשכול 19 · פגישות עם חדר — תפיסת לוח דו-כיוונית (`חנות 19 ·`)

15. `ShopEvent` מקבל `roomId?: Id` + ‏`mainEventId?: Id` (האירוע המקושר בלוח הראשי — דפוס dueEventId/nextEventId הקיים).
16. `upsertShopEvent` — כשיש roomId: (א) בדוק `roomClashError` מ-calLib (כמו EventModal, עם החרגת mainEventId בעריכה) — התנגשות ⇒ ‏toast + ‏return false, בלי שמירה; (ב) צור/עדכן OrgEvent אמיתי ב-db.events: ‏type הקיים המתאים לפגישה, ‏title="🤝 פגישת ליווי — <שם המוטב>", ‏date/time/roomId, ‏famId של השיוך; שמור mainEventId. הסרת חדר/מחיקת האירוע ⇒ מחיקת האירוע המקושר (unlinkEvent — בלי יתומים). **פגישה בלי חדר — כמו היום, מבודדת.**
17. UI: ‏ShopEventModal — שדה חדר (select חדרים פעילים, רק ל-kind==='meeting') + הצגת שגיאת התנגשות; בכרטיס השיוך, על רכיב פגישה — כפתור `📅 קביעת פגישה` שפותח את המודאל מאוכלס.
18. **עדכון ratchet הבידוד — מבוקר:** הבדיקה "dayItems לא רואה shopEvents" נשארת; הוסף בדיקות חדשות: (א) פגישה-עם-חדר יוצרת OrgEvent מקושר והתנגשות חדר נחסמת בשני הכיוונים (אירוע קיים חוסם פגישה; פגישה חוסמת אירוע חדש דרך roomClashError הקיים); (ב) מחיקת הפגישה מוחקת את המקושר; (ג) **הכסף עדיין מבודד** — הבדיקות הקיימות ללא שינוי. תעד בהערת הבדיקה: "חור מבוקר בבידוד — הכרעת בעלים 16, 30.7.2026".
