## הכרעות (מחייבות לבנייה הזאת)
1. **יכולת = שירות קריאה-בלבד של כלי.** אין כתיבה, אין אוסף חדש, אין כסף/קבלות/לוח-ראשי (`events`)/חדרי-חוגים (`rooms`);
   אין `public/c/*`, `firestore.rules`, `functions/`, workflows.
2. **כל חיבור מגודר פעמיים:** מודול-הצרכן דלוק **וגם** יכולת-הספק זמינה. אחרת — המסך **ביט-זהה** למה שהיה (מוכח בזהב).
3. **"שוקל רק מה שהדלקת":** הרישום קל; הספקים נטענים ב-`import()` דינמי, רק למודול דלוק, רק כשמסך צריך יכולת שלו.
   הכניסה (entry) לא גדלה ביותר מ-~300B gzip.
4. **אין Date.now / store / DOM ביכולת.** ההקשר מוזרק: `ctx = { db, config, nowMs }`. אותו קלט ⇒ אותו פלט.
5. **`ask` לעולם לא זורק** — מחזיר תשובה מטופסת, או "לא זמין" מטופס עם סיבה.
6. **לא בבית של אורביט** בסבב הזה (תקציר-היום רק בלשונית-הטיפול של פרנסה׳לע ובלוח-הבקרה של האירוח).

## החוזה — `src/lib/switchboard/`
| קובץ | תפקיד |
|---|---|

### זמינות (`listAbilities` / `ask`)
- מודול-הספק דלוק דרך העוזר הקיים (`moduleOn` ⇒ `moduleEnabledIn`; שני הכלים opt-in — רק `true` מדליק).
- ובאופציה — תת-הדגל של הכלי (`featureOn`), כי כלי שהבעלים כיבה חלק ממנו לא "מדבר" בשמו מחוץ לו
  (`parnasa.directory` כבוי ⇒ אין `parnasa.findPro`).
- סיבות "לא זמין": `unknown` (מזהה זר) · `off` (המודול/תת-הדגל כבוי) · `loading` (הספק עוד לא נטען) · `error` (טעינה/ריצה נכשלו — נבלע).

### תקציר-היום
`todaySummary(ctx)` עובר על כל יכולת זמינה שיש לה `today` (קלט קבוע + מנסח שורות), שואל אותה דרך `ask` ואוסף שורות
עבריות בסדר-הרישום. ספק שנכשל — שותק. כלי אחד בלבד ⇒ הכרטיס לא מוצג (אין "מערכת אחת" לאסוף).

## איך כלי חדש מצטרף — קובץ-ספק אחד + שורת-רישום אחת
1. **קובץ-ספק** בתיקיית-הכלי: `src/components/<tool>/abilities.ts`
   ```ts
   import { ability } from '../../lib/switchboard/contract';
   export interface XInput { … }      // הקלט
   export interface XOutput { … }     // הפלט
   export const abilities = {
     '<tool>.x': ability<XInput, XOutput>({
       run: (ctx, input) => …,                       // טהור: רק ctx + input
       today: { input: {…}, lines: (out, ctx) => [] }, // אופציונלי — שורות לתקציר
     }),
   };
   ```
   כללי-הקובץ (ננעלים בבדיקה): בלי `Date.now`/`new Date()`/`useApp`/`document`/`window`; קורא רק את אוספי-ה-DB שהצהיר;
   בלי מילות-כסף/לוח-ראשי; פרטים פרטיים (מבקשים, אורחים, מחירים) — לא בפלט.
2. **שורת-רישום** ב-`REGISTRY` (`src/lib/switchboard/registry.ts`):
   ```ts
   { module: '<tool>', reads: ['<col>', 'ui'], abilities: { '<tool>.x': { label: 'תווית בעברית', flag: '<tool>.<sub>' } }, load: () => import('../../components/<tool>/abilities') },
   ```
   הטיפוסים (`InputOf`/`OutputOf`) נגזרים אוטומטית מהספק; בדיקת-הרישום מוודאת שהמזהים בשורה = המזהים בספק (שני הכיוונים).

## החיבורים
- **א׳ אירוח ← לוח הקהילה** (צרכן: `hosting.shabbat`; ספק: `parnasa.shabbat` + `parnasa.minyanim`):
  · כרטיס-הזמנה קיימת ששוהה בליל-שבת ⇒ "🕯️ שבת בשהייה · מלוח הקהילה": הדלקת נרות · צאת השבת (ר״ת) · מניינים לשישי-שבת לפי
  בית-כנסת וכתובת · "📤 שליחה למשפחה" — הודעת-וואטסאפ ממולאת (זמנים + מניינים + כתובות), מגודרת בהרחבת-וואטסאפ (`lib/wa.ts`)
  ובטלפון-אורח תקין. · לשונית 🕯️ שבת ⇒ פאנל "🕯️ זמני השבת מלוח הקהילה" (השבת הקרובה + מניינים) ו-📤 בשורת-החבילות.
  · פרנסה׳לע כבוי ⇒ האירוח ממשיך עם לוגיקת-השבת שלו (שדות הזמנים הידניים, "שוהים בשבת/יו״ט" מהלוח העברי) — ביט-זהה.
- **ב׳ תחזוקה ⇒ מדריך** (צרכן: `hosting.maint`/`hosting.housekeeping`; ספק: `parnasa.findPro`, ובחירום גם `parnasa.emergency`):
  "🔧 מצא בעל מקצוע" בשורת קריאה פתוחה (ובכרטיס משימת-ניקיון פתוחה) ⇒ דיאלוג בסקין של האירוח: עד 3 בעלי-מקצוע **פתוחים
  עכשיו** (אין — הכי מתאימים, עם מצבם), ☎ קוד-חיוג, 📞 (טלפוניה) · 💬 (וואטסאפ) מגודרים בהרחבות; P0/P1/בטיחות ⇒ גם מספרי-החירום
  של הלוח. **אפס כתיבה לנתוני פרנסה׳לע.**
- **ג׳ הקו ← הכול** (`parnasa/phoneLine.ts`): קלט אופציונלי `switchboard: { ask, ctx }` — המודל לא מייבא אף כלי, רק שואל.
  `hosting.availability` זמין ⇒ מקש 5 "לבדיקת יחידת אירוח פנויה" ⇒ הלילה · מחר בלילה · השבת הקרובה ⇒ הקראת היחידות הפנויות.
  כל הכללים נשמרים: אמרו-או-הקישו (הענף מקשים בלבד) · אין פעולה בלי אישור (בענף אין פעולה בכלל) · סגור בשבת/יו״ט (השורש
  סגור) · דטרמיניזם. **בלי אירוח — העץ ביט-זהה** (זהב שנוצר מהקוד שלפני השינוי).
- **ד׳ תקציר-היום** — כרטיס "☀ תקציר היום" בלשונית 🏠 טיפול של פרנסה׳לע ובלוח-הבקרה של האירוח, רק כשכלי **שני** זמין;
  ⧉ העתקה + 💬 שיתוף בוואטסאפ — מגודרים בדגל-הייצוא של הכלי, בשער-הייצוא (`guardExport`) ובהרחבת-וואטסאפ.

## בדיקות
- **רישום:** מודול כבוי ⇒ היכולת חסרה ו-`ask` ⇒ `off`; תת-דגל כבוי ⇒ חסרה; `"true"` כמחרוזת ⇒ כבוי; מזהה זר ⇒ `unknown`;
  לא-נטען ⇒ `loading`; ריצה שזורקת ⇒ `error`; ctx פגום ⇒ `error` (לא זורק); טעינה רק למודולים דלוקים; מזהי-השורה = מזהי-הספק.
- **ספקים:** טוהר (סריקת-מקור) · דטרמיניזם (פעמיים ⇒ זהה; db מוקפא) · קריאה רק מהאוספים שהוצהרו · בידוד (מילות-כסף, `.events`,
  `db.rooms`) · פרטיות (בקשות-תושבים לא נקראות; אין מחירים/אורחים בפלט) · `findPro` = הבחירה של `resolveSpeech`.
- **חיבורים:** הגנות-מקור לכל שער + רינדור-שרת: דלוק ⇒ התוכן; כבוי ⇒ **זהב-HTML ביט-זהה** (נוצר מהקוד שלפני השינוי).
- **הקו:** זהב-JSON+תסריט ביט-זהה בלי אירוח (בלי switchboard · switchboard עם אירוח כבוי · ספק שנכשל) + ענף 5 עם אירוח.
- **תקציר:** שני כלים / אחד / אף אחד.
- **מוטציה:** כל שער נשבר בכוונה ⇒ אדום ⇒ שחזור.
- **e2e** (`e2e/toggle-matrix.mjs`): ריצה עם שני הכלים — הזמנה ⇒ זמני-השבת בכרטיס ⇒ קריאת-תחזוקה ⇒ "🔧 מצא בעל מקצוע" ⇒ האינסטלטור.
