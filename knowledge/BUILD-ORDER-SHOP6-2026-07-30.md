# 🛍 פקודת בנייה — SHOP6: חלוקה המונית · מלאי נכנס · רשימות המתנה

**מאת:** הארכיטקט · 30.7.2026 · **ענף:** `claude/what-do-you-see-bcxttj` · רץ אחרי PLATFORM (גל D בתוכנית-האב). קידומות: `חנות 25 ·`–`חנות 28 ·`. הרציונל: ראש השנה בעוד ~6 שבועות — הכאב התפעולי של חלוקת-חג ומלאי קודם לכול.

## אשכול 25 · מלאי נכנס — קליטות (`חנות 25 ·`)

**קבצים:** `types/domain.ts` · `store/persist.ts` · cloud-diff/merge · `shop/lib.ts` · `useApp.ts` · ‏StockModal → ‏`IntakePanel`.

1. ישות (קידומת `shn`; מערך `shopIntakes` — ‏18 מערכי ישויות):

```ts
/** קליטת מלאי — קנייה או תרומה-בעין. המלאי על הפריט עולה אטומית עם הרישום. */
export interface ShopIntake {
  id: Id;
  itemId: Id;
  date: IsoDate;
  qty: number;
  kind: 'buy' | 'donation';
  /** מי תרם / היכן נקנה — טקסט חופשי (בלי קישור לתורמים — בידוד). */
  source: string;
  /** עלות כוללת בש"ח — 0 בתרומה. */
  cost: number;
  note: string;
}
```

2. פעולת store: ‏`addShopIntake(intake: Omit<ShopIntake,'id'>): boolean` — דוחה qty לא-חיובי/cost שלילי (בלי לגעת ב-db); אטומית: רשומה + ‏`item.stock=(stock??0)+qty`. מחיקת קליטה (useArmed) מחזירה את המלאי (קטום ב-0) — הרשומה נמחקת (זה יומן-קליטות, לא סדרת מס).
3. ‏StockModal הקיים (חידוש מהיר) הופך לזרימת קליטה: אותו כפתור `+`, המודאל מקבל שדות kind/source/cost — כל חידוש מלאי נרשם כקליטה (ברירת kind='buy'). ‏`IntakePanel` בטאב הפריטים: יומן הקליטות (תאריך, פריט, כמות, מקור, עלות) + סה"כ עלויות.
4. **מלאי מינימום:** ‏`ShopItem.minStock?: number` — ‏needsCare kind חדש `restock` ("להצטייד: נותרו N מתחת ל-M"). ריפוי מיגרציה לשני השדות החדשים.
5. **בדיקות:** קליטה מעלה מלאי אטומית; מחיקה מחזירה וקוטמת ב-0; qty≤0 נדחה נקי; restock ב-needsCare; מיגרציה; cloud (מערך 18).

## אשכול 26 · חלוקה המונית (`חנות 26 ·`)

**קבצים:** `shop/lib.ts` · `useApp.ts` · `BulkAssignModal.tsx` (חדש) · `AssignmentsTab.tsx`.

6. ‏lib טהור: ‏`eligibleFamilies(db, criterionIds: Id[], excludeProductId: Id): { famId, name, memberIds }[]` — משפחות פעילות שיש להן (ברמת שיוך קיים כלשהו) את הקריטריונים שנבחרו **או** כל המשפחות כשלא נבחר קריטריון; מסונן ממי שכבר יש לו שיוך פעיל לאותה חבילה (אין כפל).
7. פעולת store: ‏`bulkAssignShop(productId, rows: { famId, memberId, criterionIds }[]): { ok: boolean, created: number }` — יוצר שיוכים בלולאה אטומית אחת (setDb יחיד, nextId פר-שורה); דוחה ריק.
8. ‏BulkAssignModal (כפתור `👥 שיוך המוני` בטאב המוטבים): בחירת חבילה → סינון קריטריונים → טבלת משפחות עם checkbox (ברירת הכל-מסומן) ובחירת בן-משפחה אופציונלית פר-שורה → "שייך N משפחות" (useArmed) → טוסט.
9. **רשימת חלוקה מודפסת:** כפתור `🖨 רשימת חלוקה` על חבילה — שורות טהורות ב-lib: משפחה, כתובת, טלפון, רכיבים, עמודת "☐ נמסר" — דפוס תדפיס-הרכז מ-CONNECT.
10. **חלוקה המונית של מימושים:** על חבילה עם שיוכים פעילים — `🎁 סימון חולק לכולם` (בחירת רכיב + תאריך + חג אם רלוונטי) ⇒ ‏`bulkRedeem(productId, componentId, { date, holiday }): { created }` — מימוש לכל שיוך פעיל שטרם מומש (מדלג על מי שכבר קיבל); ‏paid=0 קבוע בזרימה ההמונית (מתנת-חג/חלוקה — בלי S-; גבייה פרטנית נשארת במימוש הבודד). מלאי יורד בהתאם; אם המלאי לא מספיק — עצירה עם הודעה "חסרות K יחידות" **לפני** כל כתיבה.
11. **בדיקות:** ‏eligibleFamilies (קריטריון/בלי/כפל-מוצר); ‏bulkAssign יוצר N ולא נוגע במונים הכספיים; ‏bulkRedeem מדלג-על-שמומש, נעצר-נקי על מחסור (db זהה), מוריד מלאי נכון; שורות רשימת החלוקה.

## אשכול 27 · רשימות המתנה (`חנות 27 ·`)

12. ‏`ShopItem.waits?: { famId: Id; date: IsoDate; note: string }[]` (‏cloud-merge LIST_FIELDS: ‏shopItems:['waits']; ריפוי מיגרציה).
13. פעולות: ‏`addShopWait(itemId, famId, note)` (כפול-משפחה נדחה בטוסט) · ‏`removeShopWait(itemId, famId)`. במימוש/שיוך כשהמלאי 0 — הצעה אוטומטית "להוסיף לרשימת ההמתנה?".
14. ‏needsCare kind ‏`waitingRestocked` — פריט עם ממתינים ומלאי>0: "‏N ממתינים לסט תפילין — המלאי חזר". שורת ממתינים בפאנל הפריט (שם משפחה, תאריך, הסרה).
15. **בדיקות:** כפול נדחה; קליטת מלאי מקפיצה waitingRestocked; מלאי 0 ⇒ אין התרעה; הסרה.
