## P0.1 · מסלול מעבר נתונים מהקובץ החי (הקריטי ביותר)

**מטרה:** גיבוי JSON אמיתי מהקובץ החי נטען ב-React בלי לאבד כלום.

**עובדות מאומתות על צורת הגיבוי הלגאסי** (legacy-main-script.js:152, 170-177):
```json
{ "v": 1, "savedAt": "...", "families": [...], "enrollments": [...], "courses": [...],
  "events": [...], "rooms": [...], "orgName": "...", "orgSite": "...", "orgDonate": "...",
  "notif": {...}, "reports": {...}, "seq": N, "teachers": [...], "supporters": [...],
  "ui": { "famView": "...", "crsView": "..." } }
```
- מפתח localStorage בלגאסי: `maorclean2_db`. הייבוא אצלנו הוא דרך קובץ (ImportSection→restore), לא דרך המפתח.
- supporters בלגאסי נושאים `hist: [{d, a, c}]` (תאריך/סכום/מטבע — legacy:998 `hist: []` ברשומות חדשות, ותצוגה ב-supDonEvents legacy:1486-1495) ו-`ayin.paid` (ראה P0.4). ids עשויים להיות `spi<N>` (legacy:998).
- משפחות עשויות לשאת קידומות id `fr`/`wd`/`fb` — `migrate()` חייב לבלוע אותן כמו שהן (אין שינוי id!), רק לוודא ייחודיות members כרגיל.

**מה לבנות:**
1. `src/types/domain.ts` — להוסיף ל-`Supporter`:
   ```ts
   /** תרומות מהקובץ ההיסטורי (לגאסי hist) — לא קבלות; מוצג בכרטיס התומכת. */
   hist?: { d: IsoDate; a: number; c?: '₪' | '$' }[];
   ```
   **לא** להעלות DB_VERSION (שדה אופציונלי, אין טרנספורמציה) — אבל להוסיף normalization ב-`migrate()`: `hist` לא-מערך → undefined; איברים בלי `d`/`a` מספרי → נזרקים.
2. `src/store/persist.ts` (`migrate()`) — לוודא בליעה מלאה של הצורה שלמעלה: `orgSite`/`orgDonate` נשמרים (בדוק אם קיימים ב-Db; אם לא — להוסיף ל-`Db` כאופציונליים ולמפות), `ui.famView`/`ui.crsView` ממופים ל-ui הקיים, `teachers` נבלעים. `seq` כבר עושה max — לוודא שהוא בולע גם `spi` (parseInt לא יתפוס — הזריעה הקיימת של members עושה סריקה; להרחיב את סריקת המזהים גם ל-supporters אם עוד לא).
3. **תצוגת hist בכרטיס התומכת** — `src/components/supporters/SupporterDetail.tsx`: רשימת "כל התרומות" ממוזגת לפי הלוגיקה של legacy `supDonEvents` (1486-1495): donations (עם 'קבלה R-N') + hist ('מהקובץ ההיסטורי') ממוינים יורד; אם אין hist — שורות first/last כ"תרומה ראשונה/אחרונה (מהקובץ)". דגל: `supporters.hist` + מחרוזות termOf.
4. **בדיקות:** `src/store/__tests__/migrate-legacy.test.ts` (חדש) — fixture גיבוי לגאסי מייצג (לבנות מהצורה שלמעלה: 3 משפחות עם קידומות fr/wd/fb + members, 2 תומכות עם hist+ayin.paid+id spi, חוגים/שיבוצים/אירועים/חדרים/מורים, seq) → `migrate()` → ספירות זהות, hist נשמר, אין שינוי ids, seq ≥ המקסימום. הערת ratchet עם הפניה ל-legacy:152.
5. **e2e:** להוסיף ל-`e2e/launch-readiness.mjs` מסע "ייבוא גיבוי לגאסי" — קובץ fixture (`e2e/fixtures/legacy-backup.json`) → מסך הגדרות → שחזור → ספירות על המסך.

**קבלה:** verify ירוק · הבדיקה החדשה ירוקה · המסע החדש ירוק · גיבוי הפיקסצ׳ר עולה עם ספירות זהות.

**מה לבנות:**
1. `src/types/domain.ts` — `AyinCase` מקבל `paid?: boolean` (אופציונלי, אין מיגרציה).
2. **ייצוא** — הרחבת `src/lib/ayin.ts` בפונקציה טהורה:
   `ayinSheetRows(supporters: Supporter[]): string[][]` — כותרת ושורות **בדיוק** כמו legacy:196-198:
   `['תומכת','טלפון','שם למסירה','כמה עיניים','נמסר (כן/לא)','שולם (כן/לא)','תשובה/הערה','עופרת בוצעה (כן/לא)']`;
   פר-תומכת: כל שם ב-ayin.names → שורה; `נמסר`=n.done; `שולם`=case.paid; `תשובה`=answers[0].note או answeredNote (פסיקים→רווח); `עופרת בוצעה`='כן' אם stage∈{eyes,answer,done}. שם קובץ: `maor-ayin-eyes.csv`.
3. **ייבוא** — פונקציה טהורה `parseAyinSheet(rows: string[][], supporters: Supporter[])` המחזירה עדכונים, בדיוק לפי legacy:852-869: זיהוי עמודות לפי הכלה (`תומכת/תומך`, `שם למסירה/שם לעופרת/שם`, `עיניים`, `נמסר`, `שולם/תשלום`, `תשובה/הערה`, `עופרת`); התאמה normName(תומכת)+normName(שם); `yes()` regex: `/כן|yes|✓|v|שולם/i`; שורה בלי שום ערך → מדולגת; ואפליקציה לפי legacy:983-993: eyes השתנה → unshift ל-log {date,eyes,name}; done; paid (רמת case); answer עם דה-דופ מול answers קיימות + answeredNote; lead='כן' ו-stage∉{eyes,answer,done} → stage='eyes'; תמיד lastTouch=today. **החלה דרך פעולת store חדשה** `ayinApplySheet(upds)` שעוברת setDb (סנכרון ענן חינם).
