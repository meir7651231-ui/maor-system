## 🚫 1. אילוצים קשיחים — מה לא רלוונטי (מסנן חצי מהחדשות)

הפרויקט הוא **אתר סטטי, local-first, מסירה חד־פעמית ללקוח, אפס תחזוקה לשנים**. לכן **דלג/סנן** כל דבר שמצריך:

- **שרת / backend / API בתשלום** — אין שרת. הכול רץ בדפדפן של הלקוח.
- **מנוי חודשי / עלות חוזרת / per-seat** — המודל הוא תשלום חד־פעמי. שירות שגובה חודשי = לא רלוונטי.
- **תלות בצד־שלישי כדרישה** — חשבון ענן חובה, SaaS חיצוני, מפתח API שצריך לחדש. (Firebase קיים כ־**opt-in בלבד**; המערכת חייבת לעבוד מלא גם אופליין.)
- **חיבור אינטרנט קבוע** — חייב לעבוד לגמרי offline.
- **stack זר** — לא מהגרים מ־React. הצעות "תעבור ל־X framework" = לא רלוונטי.
- העלאת דאטה רגיש לענן ציבורי (בריאות, ת"ז, קטינים) — פרטיות היא קו אדום, לא נוחות.

## ⭐ 2. מה מאוד רלוונטי (זה מה שאני מחפש)

- **AI בעברית** — מודלים/כלים שמבינים עברית טוב, RTL, ניקוד, מורפולוגיה, שמות חרדיים.
- **כלים שרצים בדפדפן / on-device** — WASM, WebGPU, מודלים קטנים בצד־לקוח, ללא שרת (מתאים למודל ה־local-first).
- **OCR של טפסים** — סריקת דפי הרשמה/משפחות מנייר או אקסל ישן לתוך המערכת (זרימת הייבוא היא כאב אמיתי). כולל OCR עברי + windows-1255.
- **פרטיות / הצפנה בצד־לקוח** — envelope encryption, KDF, ניהול מפתחות בדפדפן, פתרונות ללא ענן.
- **לוח עברי / תאריכים** — ספריות, דיוק Intl, גימטריה, דין אדר.
- **White-label סטטי / multi-tenant בלי שרת** — הפצת אתר אחד לאינסוף לקוחות.
- **קבלות / רגולציה בישראל** — קבלות סעיף 46, ניהול ספרים דיגיטלי, סכום־במילים בעברית.
