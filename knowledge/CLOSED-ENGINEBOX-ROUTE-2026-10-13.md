## 2. ה-API

```ts
interface RoutePart { id: string; name: string; gives: readonly string[]; needs: readonly string[] }
interface RouteLink { giver: string; plug: string; needer: string }   // needer = GOAL ('@goal') ⇒ "התוצאה שביקשת"
interface RouteStep { add: string; links: RouteLink[] }
interface Route { steps: RouteStep[]; links: RouteLink[]; missing: string[]; addedCount: number }

findRoutes({ parts, start, goalPlugs, maxDepth = 4, maxRoutes = 5 }): Route[]
goalFromText(text): { plugs: string[]; matched: Array<{ word: string; plug: string }> }
routeText(route, nameOf): string[]
rankByRecipes(options /* {key}[] */, recipeCounts): T[]
```

### findRoutes — הסמנטיקה
- **זמין** = תקע שנותן מנוע-התחלה או מנוע-שנוסף. **היעד הושג** כשכל תקעי-המטרה זמינים **וגם** כל הצרכים של כל
  מנוע-שנוסף זמינים (מנוע שנוסף מביא איתו את צרכיו — אין "חצי-מנוע").
- **סדר:** פחות-חסרים → פחות מנועים-מתווספים → פחות חיבורים → לפי המזהים (ממוינים). דטרמיניסטי — אותו קלט בכל סדר
  ⇒ אותה תשובה (בדיקה).
- **מסלול לא-מינימלי לא מוצע:** קבוצה שמכילה קבוצה-פותרת קטנה ממנה = מנוע מיותר ⇒ נזרקת.
- **חיבורים (`links`)**, שלושה סוגים: (1) כל צורך של מנוע-שנוסף ← הנותן שלו (מנוע-התחלה מועדף — כבר מחובר; אחר-כך
  מנוע-שנוסף; בתוך כל קבוצה לפי מזהה; מנוע שנותן לעצמו — אין כבל); (2) כל יעד שרק מנוע-חדש נותן ← `GOAL`;
  (3) **"ושם"** — מנוע-התחלה שחיכה לתקע שרק מנוע-חדש נותן מקבל חיבור.
- **צעדים (`steps`)** בסדר-הרכבה: קודם מי שכל צרכיו כבר זמינים; מעגל (צריכים זה את זה) ⇒ הקטן לפי מזהה. כל חיבור
  משויך לצעד שבו שני קצותיו כבר בפנים.
- **מנוע חסר:**
  - יעד שאין לו נותן **בכל הארגז** ⇒ תשובה אחת בצורת-מסלול: `[{ steps: [], links: [], missing: [...], addedCount: 0 }]`.
  - צורך-ביניים שאין לו נותן ⇒ המסלול **מוצג** (לא נחסם) ו-`missing` אומר בדיוק מה לבנות; מסלול שלם תמיד לפניו.
  - אין שום מסלול בעומק המותר ⇒ `[]`.
- **מעגלים:** קבוצה לא חוזרת פעמיים (מפתח-קבוצה), מנוע לא מתווסף פעמיים, העומק חסום ⇒ תמיד נגמר. מעגל-עצמי
  (נותן ומצריך אותו תקע) נסגר בעצמו.

### האלגוריתם (למה זה מהיר)
חיפוש-לרוחב על **קבוצות** מנועים (רמה = כמה נוספו). בכל מצב: פתוחים = מבוקש ∖ זמין ∖ אין-לו-נותן. מתפצלים על
**תקע פתוח אחד** — זה עם הכי מעט נותנים — ועל נותניו: שלם (כל פתרון חייב לכלול נותן לתקע הזה) והרבה פחות ענפים.
תקעים = מסכות-ביטים; מסכות-המצב מחושבות בעצלות (רוב המצבים ברמה האחרונה לא מורחבים לעולם); חסם-תחתון
`⌈פתוחים / מקס-נתינה-למנוע⌉ ≤ עומק-שנשאר` נבדק **לפני** מיון/מפתח/כפילויות; רמה נבדקת כולה לפני שמחליטים להעמיק,
ומספיק מסלולים שלמים ⇒ עוצרים. תקרת-בטיחות 200K מצבים; `maxDepth` מוגבל ל-8.

**ביצועים (נבדק, חציון 5 ריצות):** 300 מנועים × 20 תקעים — 3 זרעים × 3 מטרות, וגם "המקרה הקשה" שבו כל מנוע צריך
1–2 תקעים והמסלולים הקצרים באורך 4 (~9,500 מצבים) — כולם מתחת ל-50ms (בפועל 2–40ms).

## 4. הכרעות (הפשוט והכן)
1. **צרכי מנוע-שנוסף — כולם** חייבים להיסגר (לא רק "מה שהיעד תלוי בו"): מנוע מגיע שלם; פשוט ונכון לתצוגה.
2. **צורך בלי שום נותן לא חוסם** — נרשם ב-`missing`. כך "Waze" מראה את הדרך ואומר "כאן חסר גשר — בנו אותו".
   מסלולים שלמים תמיד קודמים.
3. **צרכי מנועי-ההתחלה לא נדרשים** (הם כבר עובדים היום); אבל אם מנוע-חדש סוגר אחד מהם — זה חיבור שמוצג.
4. **`GOAL = '@goal'`** הוא ה"צרכן" של יעדי-המטרה; `routeText` מציג אותו כ"התוצאה שביקשת".
5. **עצירה:** אחרי רמה שיש בה ≥ maxRoutes מסלולים שלמים (העמוקים תמיד ארוכים יותר ⇒ הסדר נשמר).
6. **מזהה כפול בקטלוג** ⇒ הראשון קובע. מזהה-התחלה זר ⇒ מתעלמים.
7. **`rankByRecipes`** — מיון יציב לפי ספירה יורדת; חסר/NaN/לא-מספר = 0; לא נוגע בקלט; המפתח נבדק רק כ-own-property.

## 5. איך המשלב ממפה את הקטלוג האמיתי
```ts
import { findRoutes, goalFromText, routeText, rankByRecipes, type RoutePart } from '../engineroute';
// כל מנוע בקטלוג של enginebox ⇒ RoutePart: המזהה, השם העברי, והתקעים (זכר=gives, נקבה=needs) — מזהי-התקן בלבד.
const parts: RoutePart[] = catalog.map((e) => ({ id: e.id, name: e.name, gives: e.gives, needs: e.needs }));
const start = installedEngineIds;                  // מה שכבר דלוק בארגון (למשל לפי moduleEnabledIn)
const { plugs, matched } = goalFromText(userText);  // matched ⇒ להדגיש בממשק "הבנתי: שבת · להזמין · טלפון כשר"
const routes = findRoutes({ parts, start, goalPlugs: plugs });
const lines = routeText(routes[0], (id) => parts.find((p) => p.id === id)?.name ?? id);
// "ללמוד מכל הלקוחות": מפתח-חיבור לבחירת המשלב (למשל `${giver}>${plug}>${needer}`), ספירות מבחוץ (ענן/ריצה-לילית).
const ranked = rankByRecipes(options, recipeCounts);
```
- אם בקטלוג שמות-השדות שונים (plugs-in/out, male/female) — המיפוי הוא שורה אחת כמו למעלה.
- `missing` הוא הקלט למחולל ("חסר מנוע שנותן X").
- הלקסיקון מיוצא — אפשר להרחיב/לתרגם בלי לגעת במנוע.
